# Repositories (Ports and Adapters)

Interfaces live in `:core:domain`; adapters in `:core:data`; Hilt modules in each app bind them.
Presentation depends on the interfaces only (`PresentationIsolationTest`).

## `repository/QuranText.kt` — Quran text and surah metadata, offline

```kotlin
interface QuranText {
    suspend fun surahs(): List<Surah>          // all 114, in order
    suspend fun surah(number: Int): Surah      // throws IllegalArgumentException outside 1..114
    suspend fun ayahs(surah: Int): List<Ayah>  // Arabic + English + Bangla per ayah
}
```

**Adapter: `text/AssetQuranText`** — reads `assets/quran/surahs.json` and
`assets/quran/text/001..114.json` (compact JSON generated by `scripts/build_quran_text.py`),
parsed by the pure `text/QuranTextParser`. Keeps the 6 most recently read surahs in an
access-ordered cache; file reads run on `Dispatchers.IO`.

## `repository/QuranSettings.kt` — preferences and playback memory

```kotlin
interface QuranSettings {
    val mode: Flow<RecitationMode>             // defaults to ARABIC_BANGLA
    suspend fun setMode(mode: RecitationMode)
    val lastPosition: Flow<LastPosition?>      // null before anything has played
    suspend fun saveLastPosition(position: LastPosition)
}
```

**Adapter: `settings/DataStoreQuranSettings`** — Preferences DataStore named `quran_settings`
(keys `mode`, `last_surah`, `last_ayah`, `last_mode`); unknown stored mode names fall back to the
default.

## `repository/SurahDownloads.kt` — downloaded audio, per surah and track

```kotlin
interface SurahDownloads {
    val states: StateFlow<Map<Int, Map<Track, SurahDownloadState>>>  // absent pair = NotDownloaded
    fun download(surah: Int, tracks: List<Track>)  // queues missing files; any thread
    fun remove(surah: Int, tracks: List<Track>)    // cancels and deletes
}
```

Helpers on the states map: `stateOf(surah, track)` and `stateOf(surah, tracks)` (rolls a mode's
tracks into one state for the UI).

**Adapter: `audio/MediaSurahDownloads`** — Media3 `DownloadManager` (from `QuranCache`), one
`DownloadRequest` per verse file (download id = `QuranAudioUrls.AudioFile.id`, e.g. `"ar/255"`).
Completed files are skipped on re-download. States are derived by the pure `DownloadAggregation`
(see `domain-services.md`); listener events and an initial index load are merged under one lock so
neither can clobber the other. Removal keeps a shared basmala (`ar/1`/`en/1`) alive while any other
tracked pair still needs it. Downloading starts `QuranDownloadService` (foreground; falls back to
in-process downloading when Android 12+ forbids the background start).

## `player/QuranPlayer.kt` — ayah-by-ayah playback

```kotlin
interface QuranPlayer {
    val nowPlaying: StateFlow<NowPlaying?>      // null when nothing is queued
    val error: StateFlow<String?>               // cleared when playback resumes
    fun play(surah: Int, fromAyah: Int = 1, mode: RecitationMode)  // ayah 0 = basmala
    fun togglePlayPause()
    fun nextAyah()
    fun previousAyah()
    fun stop()
    fun restoreLast(playWhenReady: Boolean = false)  // no-op if nothing saved/already queued
}
```

**Adapter: `player/ExoQuranPlayer`** — see `media-playback.md`.
